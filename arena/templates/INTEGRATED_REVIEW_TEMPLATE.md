## 이견 이슈 상세

### 작성 규칙

- 요약문 1~2줄로 끝내지 말고, 근거 기반으로 상세 서술한다.
- 아래 항목을 **반드시 모두** 포함한다.
  - 최초제기_문제: 아래 4가지를 모두 포함
    - 배경: 어떤 기능/상태/계약 변화 맥락에서 문제를 제기했는지
    - 발생_조건: 입력/호출 경로/권한/데이터 상태
    - 실패_양상: 실제 관찰 가능한 실패(오류코드/데이터 불일치/회귀 동작)
    - 근거_코드: 문제 제기의 직접 근거 코드 위치/분기 조건
  - 최초제안_조치: 아래 4가지를 모두 포함
    - 즉시_조치: 단기 완화안(가드, 검증, 롤백/호환 처리)
    - 구조_개선: 중장기 개선안(정책 추상화, 책임 분리, 계약 정비)
    - 적용_조건: 조치 적용 시점(머지 전/다음 배포 전/후속 처리)
    - 검증_계획: 테스트/로그/재현 기준과 성공 판정 조건
  - 연관_파일: 실제 파일 경로를 2개 이상 제시 (가능하면 라인 포함)
  - 재현_조건: 입력/호출 경로/상태를 구체적으로 기술
  - 상세_분석: 왜 이견이 생겼는지, 어떤 전제 차이가 있는지, 현재 코드 기준 결론
  - 영향_평가: 실제 장애/회귀 가능성 수준과 범위
  - 필요후속조치: 검증 방법(테스트/로그/코드 탐색)과 기대 판정 기준
