# 베이스 리뷰 템플릿

## 메타 정보

- 리뷰어_모델: `{model}`
- 리뷰어_페르소나: `{persona}`
- 대상_브랜치: `{current-branch-name}`
- 검토_범위: `{git diff 범위 또는 파일 목록}`
- 리뷰_일자: `{YYYY-MM-DD}`

## 작성 규칙

- 반드시 **실제 코드에 존재하는 심볼/메서드/에러코드만** 언급한다.
- `리뷰어_모델`은 실행 파라미터 `{model}` 값을 그대로 사용한다. (예: `gpt5`, `claude-sonnet-4-6`)
- 페르소나는 `리뷰어_페르소나`에만 기록하고 `리뷰어_모델` 값을 대체하지 않는다.
- `severity`는 `P1: 매우 심각 (릴리즈/머지 차단급, 즉시 수정)|P2: 보통 (중요하지만 단기 내 계획 수정 가능, 보통 다음 배포 전)|P3: 경미 (개선/리팩터링 성격, 후속 처리 가능)`만 사용한다.
- `confidence`는 `0.00~1.00` 숫자로 작성한다.
- 모든 finding에 `evidence`(절대경로 + line)와 `impact`를 포함한다.
- 추측성 문구(예: “~일 수 있음”만 반복) 대신 재현 조건을 한 문장으로 쓴다.
- 표는 **요약 인덱스 용도**로만 사용한다.
- 표 셀 텍스트는 가능한 1문장, 12단어 이내로 작성한다.
- 긴 설명/근거/수정안은 표에 쓰지 않고 `이슈 상세`에 작성한다.

## 심각도 표기 표준

- `P1: 매우 심각 (릴리즈/머지 차단급, 즉시 수정)`
- `P2: 보통 (중요하지만 단기 내 계획 수정 가능, 보통 다음 배포 전)`
- `P3: 경미 (개선/리팩터링 성격, 후속 처리 가능)`

## 이슈 상세

### 이슈-001

- 심각도: `P1: 매우 심각 (릴리즈/머지 차단급, 즉시 수정)`
- 신뢰도: `0.90`
- 근거: `/abs/path/File.java` (line 123), `/abs/path/Other.java` (line 88)
- 재현조건: `기존 map 포맷으로 submit 호출`
- 영향: `INVALID_REQUEST(400)로 제출 기능 중단`
- 수정안: `fallback 파싱 또는 v2 엔드포인트 분리`

### 이슈-002

- 심각도: `P2: 보통 (중요하지만 단기 내 계획 수정 가능, 보통 다음 배포 전)`
- 신뢰도: `0.80`
- 근거: `/abs/path/File.java` (line 45)
- 재현조건: `signerName 101자 이상 입력`
- 영향: `DB 길이 제약 충돌로 예외 가능`
- 수정안: `서비스 길이 검증 + DTO @Size(max=100)`

## 이슈 없음 규칙

- finding이 없으면 아래 한 줄만 작성:
`No findings. Residual risk: {테스트 미실행/환경 제약}`
